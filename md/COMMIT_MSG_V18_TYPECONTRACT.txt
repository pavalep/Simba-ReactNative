V18: add type contract section to spec + mark V18.0.2 superseded in tracker

Two design corrections to the V18 spec, surfaced during Wave 1 kickoff:

1. Type Contract is now the keystone. New Section 2 spells out the
   before/after type contract:
   - *Raw DTOs (server shape) vs *Result DTOs (domain shape)
   - Convertor signatures: (raw | undefined) => Result | null (single)
     or (raw | undefined) => Result[] (list)
   - Service functions always return Promise<DomainType>, never Promise<Raw>
   - useApiQuery<TResult> is generic over the domain type, not the raw
   - File organization: 1 file for small services, 2 (types + adapter)
     for large services like Internet Archive

2. V18.0.2 is superseded. The original brief claimed 8 dead methods;
   `grep` across src/ proved only 1 was actually dead
   (getAudiusTracksByGenre, removed in V18.0.1). The other 7 have
   active call sites in mounted screens (useGenreScreen, useMusicScreen,
   useAudiobooksScreen, useRadioBrowser) and must be MIGRATED, not
   deleted. Per the manager's "skip V18.0 entirely" call, V18.0
   ends at V18.0.1; the 6 live methods are migrated in V18.3+.

Also updates the dead-method count in the spec's scale table
(8 -> 1) and risk register item #5 (now realized).

No code changes.
