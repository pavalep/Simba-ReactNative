V18.3.1 + V18.3.2: 5 simple search-service adapters

Creates 5 new adapter files following the V18.2 pilot pattern
(see SPEC §2 + the weatherAdapter for the canonical example).

  - src/services/api/audiusAdapter.ts    (3 methods)
  - src/services/api/jamendoAdapter.ts   (4 methods, includes the
                                         popularity-order fallback
                                         chain in getPopularJamendoTracks)
  - src/services/api/librivoxAdapter.ts  (5 methods, includes the
                                         searchByGenre 2-attempt
                                         fallback)
  - src/services/api/musicbrainzAdapter.ts (4 methods, includes
                                         the 2-call getReleaseGroupDetail
                                         flow + media.tracks.recording
                                         flatten)
  - src/services/api/tvmazeAdapter.ts    (5 methods, only
                                         searchShows has a convertor
                                         — others return the wire
                                         shape directly because
                                         TVMazeShow/TVMazeEpisode
                                         ARE the domain types)

Per-adapter structure (junior-dev rule, 1 import):
  import {
    searchShows, getShowById,
    type TVMazeShow, type TVMazeEpisode,
  } from '../services/api/tvmazeAdapter';

The 5 OLD service files (audiusService, jamendoService,
librivoxService, musicbrainzService, tvmazeService) are NOT
deleted yet — they are still imported by screen hooks and
index.ts re-exports. V18.3.3 will migrate the consumer
hooks to useApiQuery; V18.3.4 will delete the old files
and the index.ts re-exports.

Test file: __tests__/simpleAdapters.test.ts (1 file with 5
describe blocks). 18 tests covering the per-adapter convertor
contracts (happy / missing / undefined / edge cases). The
"simple" services have lighter coverage than the weather
pilot because the convertors are simpler — the heavier
test work will come in V18.4 (paginated services with
numFound/hasMore edges) and V18.5 (Internet Archive with
the 32-call surface).

Verification:
- npx tsc --noEmit  -> 0 errors
- npx jest          -> 54 passed / 1 todo / 7 suites
                       (was 36 / 1 / 6 at end of V18.2.4;
                        +18 tests, no regressions)
