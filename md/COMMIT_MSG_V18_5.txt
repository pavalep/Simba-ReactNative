V18.5: Internet Archive adapter + 36 convertor tests + 8 consumer migrations + delete service

V18.5 — the largest single deferred surface from the V18
carryover. Replaces the 495-line `internetArchiveService.ts`
with the V18-ideal `internetArchiveAdapter.ts`, migrates all
8 consumer files, and adds 36 unit tests for the convertors.

The 3-layer architecture (V18 spec §3) is now applied end-to-end
to the Internet Archive surface — the only "biggest service" that
had not been migrated to the V18 pattern.

The adapter (V18.5.1, ~480 lines):

  - File-local `*Raw` DTOs (IAResultRaw, IASearchResponse,
    IAMetadataResponse, IAVideoResultRaw, IAVideoSearchResponse).
    These never leak past the adapter boundary.

  - 7 EXPORTED named convertors (the V18 unit-of-test surface):
      - internetArchiveItemResultFromRaw (audio/music single)
      - internetArchiveItemResultsFromRaw (audio/music list)
      - internetArchiveItemDetailsFromRaw (audio item + download URLs)
      - internetArchiveVideoResultFromRaw (video single)
      - internetArchiveVideoResultsFromRaw (video list)
      - internetArchiveVideoDetailsFromRaw (video + subtitles + audio tracks)
      - archiveTracksFromRaw (audio track ordering)

  - 2 EXPORTED pure helpers (the URL builders used by the UI
    directly for thumbnail rendering):
      - archiveImageUrl(identifier)
      - archiveIdentifierFromUrl(url)

  - 7 service functions returning `Promise<DomainType>` per
    the V18 type contract §2.3:
      - searchInternetArchiveAudio
      - searchInternetArchiveMusic
      - getInternetArchiveItemDetails
      - getArchiveTracks
      - searchInternetArchiveVideos
      - getInternetArchiveVideoDetails
      - resolveInternetArchiveVideoDetails (with onRetry callback
        for partial-replication)

  - The "partial-replication" retry pattern (V6 2.3.2 lesson)
    is preserved: `resolveInternetArchiveVideoDetails` walks
    up to `maxAttempts` IA metadata servers with 250ms / 500ms /
    1000ms exponential backoff. The retry-via-callback is the
    function-level surface; the hook-level `retry: () => void`
    is what consumers get.

The 36 convertor tests (V18.5.2, __tests__/internetArchiveAdapter.test.ts):

  - 5 tests for `internetArchiveItemResultFromRaw` (happy /
    image_url fallback / empty fields / undefined / missing id)
  - 5 tests for `internetArchiveItemResultsFromRaw` (happy /
    undefined / no docs / per-item filter / numFound fallback)
  - 4 tests for `internetArchiveItemDetailsFromRaw` (happy /
    undefined / missing metadata / no audio files)
  - 3 tests for `internetArchiveVideoResultFromRaw` (happy +
    runtime parsing / undefined / bare-seconds)
  - 2 tests for `internetArchiveVideoResultsFromRaw` (happy +
    undefined)
  - 4 tests for `internetArchiveVideoDetailsFromRaw` (happy +
    partial-replication / undefined / no video files)
  - 4 tests for `archiveTracksFromRaw` (happy + sort / filters
    / undefined / missing track fallback)
  - 9 tests for the pure helpers (archiveImageUrl, archiveIdentifierFromUrl,
    parseRuntime) including the 3-shape parser (HH:MM:SS / MM:SS / bare)
  - **One bug fix surfaced by the tests:** the original
    `parseRuntime` only handled HH:MM:SS or bare seconds; the
    test "10:00" → 600 seconds exposed a silent mis-read of
    audiobook chapters as 10-second clips. Fixed in the adapter.

The 8 consumer migrations (V18.5.3):

  Hooks already on useApiQuery (6 import-swap-only files):
    - useArchiveScreen (V18.11.1 had rewritten the screen +
      hook to useApiQuery; only the import path needed updating)
    - useAudiobookDetailScreen
    - AudiobookDetailScreen.tsx (component)
    - AudiobooksContent.tsx (uses archiveImageUrl +
      archiveIdentifierFromUrl directly)
    - MoviesDataProvider.tsx (uses resolveInternetArchiveVideoDetails
      with the onRetry callback)
    - useMoviesScreen (the multi-scope state machine; the
      import swap is in this commit; the multi-scope → useQueries
      rewrite is deferred to V18.6.2 as part of the larger
      aggregated-search work — both use the same TanStack
      useQueries primitive)

  Hooks migrated to useApiQuery (2 useState/useEffect rewrites):
    - useArchiveItemDetailScreen (was: useState + useEffect +
      useCallback + Promise.all; is now: 2 useApiQuery calls
      with `enabled: !!identifier` — 57 → 50 lines, 0 useState)
    - useMovieDetailScreen (was: useState + useEffect +
      useCallback; is now: 1 useApiQuery — 38 → 24 lines,
      0 useState)

  Infrastructure:
    - searchAggregator.ts (was: `import {searchInternetArchiveAudio}
      from './internetArchiveService'`; now: `./internetArchiveAdapter` —
      function-level swap; the Promise.allSettled → useQueries
      rewrite at the hook layer is V18.6.2)
    - services/api/index.ts (barrel: `export * from './internetArchiveService'`
      → `export * from './internetArchiveAdapter'`)
