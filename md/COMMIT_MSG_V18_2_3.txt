V18.2.3: migrate useWeather to useApiQuery (pilot hook)

Migrates the Home greeting's data hook to the V18 query layer.
This is the pilot — if this design doesn't feel right, the
rest of the per-service waves (V18.3+) stop here.

What was removed from useWeather.ts:
- `useRef(didFetch)` — TanStack's `enabled` flag replaces the
  StrictMode double-invoke guard.
- `useEffect` that fired the cascade on mount — TanStack IS the
  state machine; the queryFn runs when `enabled` is true.
- `async function fetchWeatherThunk()` at the bottom of the
  file (with its 6 lazy `await import(...)` calls) — the
  cascade moves into a top-level `async function weatherCascade()`
  imported statically, called by `useApiQuery` as the queryFn.
- All `console.log` lines from the old thunk path (those were
  removed in V16 already; the new path is silent by default).

What stays:
- The 4-tier cascade itself: coords -> manual homeCity ->
  IANA timezone -> locale country. TanStack does not
  restructure the cascade; it just runs the queryFn and
  caches the result. The cascade's job is "what to fetch";
  TanStack's job is "when to fetch + retry + dedup".
- The persisted `useWeatherStore` (zustand + AsyncStorage).
  The store remains the UI's source of truth; the hook
  mirrors TanStack's result into the store via a single
  useEffect on `[data, error, isLoading]`.
- The 1-hour TTL: `shouldFetch = fetchedAt === 0 || isStale`
  + TanStack's `staleTime: ONE_HOUR_MS`. Two layers of
  cache-protection so we never hammer Open-Meteo.

Also:
- src/screens/Home/hooks/useHomeScreen.ts: import path
  changed from weatherService to weatherAdapter (the type
  `WeatherSnapshot` is now re-exported by neither — the
  consumer imports it directly from the adapter).
- src/services/api/weatherService.ts: DELETED. The old
  service file is fully superseded by the adapter.

What I deliberately did NOT do:
- Did not split the cascade into 4 parallel `useApiQuery`
  calls (one per source). That's a real refactor with a
  real behavior change (parallel vs sequential, "pick the
  best" vs "try in order"). The pilot preserves the
  cascade's existing semantics; if the user wants the
  parallel variant, that's a follow-up.
- Did not write a hook-level test for useWeather. The
  convertor tests (V18.2.2) cover the data shape; the
  store logic is unchanged. A hook test would need to
  mock the geolocation + cascade helpers, which is more
  setup than signal for the pilot. (V18.2.4 will note this
  as a follow-up if needed.)

Verification:
- npx tsc --noEmit  -> 0 errors
- npx jest          -> 36 passed / 1 todo / 6 suites
  (no new tests; no regressions)
