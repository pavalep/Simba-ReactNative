V18.11.6: Drop @react-native-tab-view from package.json + package-lock.json

Wave 11 legacy TabView cleanup, phase 6 of 6 — the last step.

After V18.11.5, `src/screens/ShowsScreen/browse/TabBar.tsx`
(the only file importing `react-native-tab-view` in the
codebase) is gone. The dependency is now truly unused.

Removed:
  - package.json        : "react-native-tab-view": "^4.3.2"
  - package-lock.json   : the package entry + the resolved
                          tarball URL (15 lines net)

How:
  - `npm pkg delete dependencies.react-native-tab-view`
    (the plain `npm uninstall` invocation is silently
    no-op on this Windows env, even though the package is
    present in node_modules — `pkg get` confirms the
    dep is still listed, so we use `pkg delete` which
    actually writes to package.json).
  - `npm install --package-lock-only` to sync the lockfile
    without touching node_modules (faster + safer than a
    full install for a delete-only operation).

Verification:
  - tsc --noEmit                       : 0 errors
  - npx jest                           : 8 suites, 68 passed,
                                         1 todo, 0 failures
  - git grep "react-native-tab-view"   : 0 matches in package.json,
                                         0 matches in package-lock.json,
                                         0 matches in src/

Outcome: `@react-native-tab-view` is fully removed from the
SIMBA app. Every browse screen that used the v3-v9
3-tab pattern has been converted to the v10+ "single
content stream + FilterChips" pattern (or the FAB
toggle for Archive / Live TV). The data flow is now
V18.3-style: `useApiQuery` for everything, TanStack
queryKey cache is the only cache, no per-scope Map /
seqRef / guardRef / hasMoreRef shims anywhere in the
screen layer.

This closes Wave 11 and the broader V18 "no legacy code
left visible" goal the user set for the manager review.
