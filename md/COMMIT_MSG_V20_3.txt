V20.3: usePodcastDetailScreen rewrite — 7 useStates + 4 useRefs + dedupeEpisodes gone (203 → ~120 effective)

V20.3 — the third batch in the V20 sweep. Rewrites
`usePodcastDetailScreen` + updates the screen consumer for
the `reachedEnd → hasMore` change. The pre-V18 implementation
was 203 lines with 7 useStates (data triple + max + hasLoaded
+ isLoading + isLoadingMore + error), 4 useRefs (seqRef for
stale-response cancellation, inFlightRef for in-flight
dedup, lastLoadMoreAtRef for the 600ms scroll throttle,
loadMoreRef as a "latest function" ref), a `Promise.all` for
the parallel podcast+episodes fetch duplicated in both the
initial effect AND the retry callback, and a `dedupeEpisodes`
helper at the bottom of the file. The V18-ideal version
is ~120 lines: 1 `useApiQuery` for the podcast metadata + 1
`useInfiniteApiQuery` for the episodes, 0 useState, 0 useRef,
0 dedupe helper.

What was removed (the legacy code):

  - 7 useStates → 0 useState for data (the `retry` useCallback
    stays; the rest of the state is in TanStack)
  - 4 useRefs (seqRef, inFlightRef, lastLoadMoreAtRef,
    loadMoreRef)
  - The 2 `Promise.all` blocks (initial + retry; the
    duplicate logic is gone — both are now a single
    `useApiQuery` + `useInfiniteApiQuery`)
  - The `dedupeEpisodes(prev, next)` helper at the bottom
    of the file (TanStack's `pages.flat()` already gives
    the union; if the API re-emits, the new `useInfiniteApiQuery`
    is internally consistent)
  - The 3-mode `fetchInitial / loadMore / retry` set of
    duplicated data-flow paths

What was added (the V18-ideal pattern):

  - `useApiQuery<PodcastResult | null>` for the podcast
    metadata. `staleTime: 5 * 60_000` (metadata doesn't
    change often). `enabled: podcastId > 0` (no fetch on
    a 0 id).
  - `useInfiniteApiQuery<PodcastEpisodeResult[]>` for the
    episodes with the same `pageParam` = doubling `max`
    pattern as V20.2. `staleTime: 60_000`.
  - `hasMore: q.hasNextPage` (the legacy `reachedEnd` is
    the inverse — `!hasMore` — and lives in the consumer
    in the one place it's used)
  - `error`: combined from `podcastQ.error ?? episodesQ.error`,
    string-coerced. The first error wins.
  - `retry`: `void podcastQ.refetch(); void episodesQ.refetch()`
    — one line, fires both refetches.

Junior-dev rule:

  - Adapter author: 1 file (V18.4.2).
  - Hook author: 1 `useApiQuery` + 1 `useInfiniteApiQuery`.
    The whole hook is 2 query calls + 3 small callbacks.
  - Screen author: 1 `usePodcastDetailScreen(podcastId)`
    call. The `reachedEnd` derivation (`!hasMore &&
    hasLoaded && episodes.length > 0`) lives in the
    consumer at the one place it's used.
