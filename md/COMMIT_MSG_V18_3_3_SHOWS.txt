V18.3.3 (batch 6): migrate useShowsScreen + screen (10/11 done)

The third "complex" hook — 3 tabs (search / today / browse) with
per-scope cache + infinite scroll on the browse tab + network
status-driven auto-retry. Similar pattern to the Audiobooks
migration.

### Hook design

Three named useApiQuery / useInfiniteApiQuery results — one
per tab:

  - search:  useApiQuery({enabled: !!searchTerm})  → TVMazeShow[]
  - today:   useApiQuery                              → TVMazeShow[]
            (the queryFn fetches the schedule and dedupes
             by show id; the dedupe lives in the queryFn)
  - browse:  useInfiniteApiQuery                      → TVMazeShow[]
            (TVMaze 250-per-page; getNextPageParam stops
             when lastPage.length < PAGE_SIZE)

The screen owns `selectedTab` via local useState. The active
scope is selected by mapping selectedTab → search/today/browse.
TanStack's cache preserves each tab's data when the user
switches.

### Files

- src/screens/ShowsScreen/hooks/useShowsScreen.ts
  318 → 233 LOC. The Map<key, ShowScopeState> + seqRef +
  guardRef + hasMoreRef + failedRef (the entire stale-response
  machinery) is gone. 3 queries handle the per-scope state.
  The new `ShowScope` type replaces `ShowScopeState`.

- src/screens/ShowsScreen/components/ShowsScreen.tsx
  Updated the screen + the `ShowTabScene` component:
  - `ShowTabSceneProps` drops `ensureLoaded`, `loadMore`,
    `retry`, `handleRefresh`, `refreshing`. The scene uses
    `scope.fetchNextPage()` and `scope.refetch()` directly.
  - The `ensureLoadedRef.current(tab)` useEffect is gone
    (queries auto-run when their `enabled` flag is true).
  - The SearchBar uses a single `searchTerm` (TanStack
    collapses concurrent fetches for the same queryKey, so
    no debounce is needed).
  - RefreshControl's `refreshing` prop is now
    `isLoading && hasLoaded` (from the scope) instead of
    the parent-managed `refreshing` state.

### What didn't change

- The 3 lazy-mounted TabView scenes still render the same way.
- The genre chip behavior (P53) still works — `initialGenre`
  pre-selects the browse tab on mount.
- The auto-retry on reconnect still works (the `useNetworkStatus`
  integration is preserved; we just call `refetch()` instead
  of the old `fetchPage`).
