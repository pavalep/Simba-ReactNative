## 1. Strategy (from the 2026-08-26 coverage report)

- **Wave 1 (small + unblocks runtime validation):** B1, L4, M5, X2. Each is a 1- to 3-file change.
- **Wave 2 (Phase 2 — video controls parity):** the 12 video control gaps, one control at a time. Backend already exists in `VideoCommands` / `VideoIntentController` / `VideoControlLayer`. Pure wiring.
- **Wave 3 (Phase 4 — audio cleanup):** sleep timer, speed UI, lyrics/info/share/more wiring, chapters display, dead `AudioActionStrip`, sheet/panel split-brain, hook `useMemo` deps, bookmark scope, etc.
- **Wave 4 (engine polish leftovers):** P1, P2, P3, P4, P5, R3, E5, M3, L2, L3, B1 follow-ups.
- **Wave 5 (page design — Phase 3):** mini↔full animation, status positioning, hardcoded colors, scrub UX, first-frame retry, drag-to-dismiss mini.

**Order rationale:** Wave 1 unblocks the runtime evidence we need before adding presentation surface area. Each Wave 2 item then becomes a one-line wiring change with confidence that the engine underneath it is telling the truth.

## 9. Retrospectives

### Wave 1 retrospective — 2026-08-26 (closed)

- **Surprises**
  - The "zero importers" claim for `ChapterList` was true for the import graph, but two audio files (`AudioTypes.ts:5`, `useAudioPlayerScreen.ts:59`) imported the `Chapter` **type** from it. Deleting the component broke the type. Fixed by hoisting a 4-field `Chapter` interface into `AudioTypes.ts` and re-importing from there. Lesson: when "dead" components export shared types, the deletion is a typed module migration, not a pure removal.
  - Deletion policy blocked `Remove-Item` and `mavis-trash` at the agent shell layer; had to use a `tools/_dead_code_archive_*/` folder. Build was unaffected because the files were outside `src/`, but `tsc` still scanned the archive until I added it to `tsconfig.json` `exclude`. Same risk for `graphify` auto-scan — should add `.graphifyignore` rule later.
- **Knock-on effects**
  - `B1` made the JS event contract wider; `player.api.ts` had no shape to change because the `on(...)` listener is generic. No caller updates needed.
  - `M5` changed the JNI signature. Anyone hand-testing the bridge on the device will need a clean rebuild of the native lib (`./gradlew clean` then `./gradlew assembleDebug`).
  - `X2` requires the user to physically remove the archive folder from their own PowerShell when convenient. The build is clean either way.
- **Findings discovered while fixing**
  - `videoReconfig` in `VideoMpvSession.ts:539-546` clears the first-frame watchdog and applies pending start. If the watchdog fires **before** `videoReconfig` arrives, `setError` is called with `recoverable: true` — but at this layer the error is "video did not produce a first frame", which IS recoverable (the user can retry). The M5 change correctly preserves recoverability here because the watchdog is not from a fatal native event. No code change needed.
  - The `playback-restart` reducer case has a guard `if (!snapshot.isBuffering) return snapshot;` so it doesn't force a phase recompute when nothing changed. This matches the spec in the audit ("ending paused-for-cache doesn't change the pause property so no state event fires").
- **Acceptance gate**
  - ✅ `tsc --noEmit` exits 0.
  - ✅ `grep -r "TrackSelectionPopup\|ChapterList\|usePlayerGestures\|AudioActionStrip" src/` returns no hits.
  - ⏸ Runtime validation (rapid seek-then-pause, PiP open+close, fatal error path) requires an APK install — the user can run a smoke test before Wave 2 starts.
- **Time spent:** 1 session, ~12 file edits, 0 deletions (moved to archive).
