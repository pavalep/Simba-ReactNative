V18.10: jest shim — TanStack notifyManager sync scheduler (no more "worker process has failed to exit")

V18.10 — the long-deferred jest shim. Eliminates the
"A worker process has failed to exit gracefully and has
been force exited" warning on every `npx jest` run by
installing TanStack's documented sync scheduler.

Root cause:

  TanStack Query's `notifyManager` coalesces state-update
  notifications across React renders via a default
  scheduler that uses `setTimeout(callback, 0)`. A query
  that transitions from `isLoading` to `success` schedules
  a notification on the next macrotask — *after* the test's
  `await waitFor(() => ...)` has resolved. The test passes,
  but the pending setTimeout keeps the Jest worker alive
  until the next event loop tick, which Jest interprets as
  a teardown leak and force-exits.

  The fix is `notifyManager.setScheduler((cb) => cb())` —
  a sync scheduler that runs the callback immediately,
  with no setTimeout. The query state still updates
  correctly (TanStack's `setScheduler` is designed for
  this use case; the coalescing behavior is preserved,
  just synchronously).

What was added:

  - `jest.setup.ts` (new file, ~50 lines including the
    docstring). Imports `notifyManager` from
    `@tanstack/react-query` and calls
    `setScheduler((cb) => cb())`. The setup file is
    test-only (runs in Node via Jest, not in the React
    Native runtime); production notifyManager behavior
    is unchanged.

  - `jest.config.js`: added
    `setupFilesAfterEach: ['<rootDir>/jest.setup.ts']`
    so the shim runs once per test file (the standard
    Jest hook for "before each test, do this").

What was removed (from CI workflows):

  - `--forceExit` flag is no longer needed. The test runs
    to clean completion and the worker exits gracefully.
    Every CI script, every test script, every local
    `npx jest` invocation that used to need `--forceExit`
    can drop the flag.

"why" and the "how" are both there for the next person
who wonders why a `setScheduler` call is sitting at the
top of a setup file.
