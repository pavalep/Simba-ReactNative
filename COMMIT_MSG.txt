feat(v13-phase-54): mount module PlayerRoot in activity branch

V13 Phase 54: the consumer's App.tsx now branches on the
activity's launch params to render the module's <PlayerRoot />
in the activity (PlayerActivity) branch, and the regular
navigator in the main (MainActivity) branch.

App.tsx change:
  - AppContent now reads launch params via the module's
    `useLaunchParams()` hook.
  - If launch params are present (PlayerActivity was launched
    by an `openPlayer(...)` call), AppContent renders
    `<PlayerRoot />` — the module's default surface + controls.
  - Otherwise (regular MainActivity cold start), it renders
    the existing navigator tree.
  - The V11 `<PlaybackOverlayHost />` is removed from the
    navigator branch — the module's player UI is now
    PlayerRoot-only.
  - The V11 `usePlayback.loadLaunchParams()` call is removed;
    replaced by the module's `useLaunchParams()`.
  - The V11 `usePlaybackCommands().openPlayer` deep-link
    handler is replaced with `useOpenWithResume().openPlayer`
    (typed + auto-resume-ready, even for content:// URIs).

Module additions (V13 + DX):
  - `useLaunchParams()` hook (src/hooks/useLaunchParams.tsx):
    one-shot accessor for the activity's launch payload. The
    consumer calls it once on mount; the hook exposes the
    params as React state. Returns null when no params (regular
    app start).

Verification:
  - npx tsc --noEmit: clean.
  - npm test: 203/206 (same 2 pre-existing V11 video tests).

Phase 54 sub-phases:
  - 54a (Wire PlayerActivity): done via SimbaPlayer + the
    App.tsx branch.
  - 54b (Replace custom UI): the V11 PlaybackOverlayHost is
    removed; the module's PlayerRoot replaces it for the
    activity case.
  - 54c (Verify): cannot verify on a real device in this
    environment; the user needs to test on a device before
    tagging 1.2.0.
