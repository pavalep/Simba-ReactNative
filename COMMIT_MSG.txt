feat(v13-phase-53b-53c): migrate notificationService + TransportContext to module bridge

V13 Phase 53 Batch 2: the two "complex" services that use the event
subscription API.

notificationService.ts (53b.6 + 53c.1):
- Routes `isNotificationActive` and `requestNotificationPermission`
  through `getMpvPlayerModule()` (the typed V13 bridge has both
  methods).
- The four V11-only methods (`startNotification`, `updateNotification`,
  `stopNotification`) stay on `NativeModules.MpvPlayerModule` directly
  with a local typed cast. They're NOT in the V13 module bridge because
  V12's MediaPlaybackService handles the foreground notification
  natively — these calls are dead code in the default V12+ flow and
  only kept for the V11 emergency rollback path.
- The V11 notification event channel (`onNotificationPlay`,
  `onNotificationPause`, etc.) is NOT part of the module's typed
  `PlayerEventName` union, so `notificationEmitter` stays as-is. The
  module's `subscribePlayerEvent` handles the 22 mpv events; the V11
  notification events live on a separate native channel.

TransportContext.tsx (53b.7 + 53c.2):
- Resolves `const bridge = useMemo(() => getMpvPlayerModule(), [])`
  once at provider mount.
- Replaces 8 `MpvPlayer.on(event, handler)` calls with
  `subscribePlayerEvent(event, handler)` from the module. The event
  names + payload shapes are identical to the V11 ones; only the call
  site moved into the module.
- Replaces `MpvPlayer.setProperty`, `getProperty`, `pause`, `resume`
  (mapped to `play`), `getPosition`, `getDuration`, `getPlaybackState`,
  `seekTo` (mapped to `seekAbsolute`), `observeProperty`,
  `unobserveProperty` with their `bridge.X()` equivalents.
- `MpvPlayer.resume()` -> `bridge.play()` (the module consolidates
  resume into the canonical `play` RPC; semantically identical).
- `MpvPlayer.seekTo(secs)` -> `bridge.seekAbsolute(secs)` (both take
  seconds, semantically identical).
- The 1Hz position/duration poll now uses `bridge.getPosition` /
  `bridge.getDuration` / `bridge.getPlaybackState`.
- The sleep-timer volume-fade logic now uses `bridge.setProperty('volume', ...)`
  and `bridge.getProperty('volume')`.
- Cleanup `unsubPosition()` etc. unchanged — the module's
  `subscribePlayerEvent` returns the same `() => void` unsubscribe
  shape as the V11 `MpvPlayer.on`.
- `MpvPlaybackState` is re-exported from the module for downstream
  consumers that dispatch Redux actions based on the typed state.
