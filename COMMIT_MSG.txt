feat(v13-dx): wire SimbaPlayer wrapper in App.tsx with bookmark lookup

V13: replace the V11 <PlaybackProvider> with the module's
<SimbaPlayer> wrapper. The wrapper composes PlayerProvider +
PlayerResumeProvider so the consumer's App.tsx is a true
one-import, one-wrapper integration.

App.tsx change (minimal):
  - Import: {SimbaPlayer, type PlayerResumeLookup} from
    '@simba-dev/react-native-media-player'
  - <PlaybackProvider> -> <SimbaPlayer lookup={resumeLookup}>
  - Lookup reads from the consumer's Redux bookmark slice and
    returns the most recent bookmark position (seconds -> ms)
    for a given file URI. Screens that pass `resumeId: item.uri`
    in their openPlayer call get auto-resume.

The wrapper is the canonical "junior-dev integration point" for
the module:
  - One import
  - One wrapper component
  - One optional lookup function (can be omitted for non-bookmark
    apps)

This is the public-facing surface for any consumer of
@simba-dev/react-native-media-player. Module exports <SimbaPlayer>
from the index. Documentation in the JSDoc explains the
provider composition + the lookup adapter contract.

The 32 screen files continue to use `usePlayerActivity().openPlayer`
(per the V13 spec migration). They can opt into
`useOpenWithResume` for auto-resume in a follow-up by passing
`resumeId: item.uri` (the lookup is keyed by fileUri).
