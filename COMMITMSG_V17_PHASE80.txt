V17 Phase 80: mediaStore (persist, fix N+1 buildSearchIndex)

`mediaSlice` → `useMediaStore` (zustand + persist, key='media',
version=1, same persist key as the redux-persist whitelist).

V16 out-of-scope fix that V17 picked up: the `searchIndex` is
no longer stored in slice state. The old slice rebuilt the entire
inverted index on every `setTracks` / `addTracks` / `removeTrack`
/ `clearTracks` action (N+1: 1 track change = re-index all
tracks). The new store has `buildSearchIndex` as a pure function
plus `useMediaSearchIndex()` as a hook that memoizes on the
`tracks` reference — the same index is returned as long as
`tracks` is unchanged. `useSearch` and other search-heavy
consumers re-render only when `tracks` actually changes.

The old `rebuildSearchIndex` action is now a no-op (kept as a
function so existing dispatch call sites don't crash; new code
should just leave it out).

New derived hooks (all `useMemo` on `tracks`):
- `useMediaSearchIndex()` → SearchIndex
- `useMediaArtists()` → ArtistEntry[] (was `selectArtists`)
- `useMediaAlbums()` → AlbumEntry[] (was `selectAlbums`)
- `useMediaAudioTracks()` → ScannedTrack[] (was `selectAudioTracks`)
- `useMediaVideoTracks()` → ScannedTrack[] (was `selectVideoTracks`)
- `useMediaLocalVideos()` → ScannedTrack[] (was `selectLocalVideos`)
