V17 Phase 82: playlistsStore + recentHistoryStore (persist, batched)

Two more persisted zustand stores replace their redux-feature
counterparts. The slice files are at the same level as the
auth/session ones from Phases 77-78, so the same persist-key +
version=1 contract applies.

`playlistReducer` (Redux + redux-persist whitelist +
`REHYDRATE` extraReducer) -> `usePlaylistsStore` (Zustand +
persist, key='playlists' to match the whitelist). The legacy
`MIXED` playlist kind is split into `AUDIO_ONLY` +
`VIDEO_ONLY` siblings by `splitLegacyMixed`, and the new
`onRehydrateStorage` callback runs `normalizePersistedPlaylists`
on the rehydrated state so old persisted shapes fold in cleanly.

`recentHistoryReducer` (Redux + redux-persist whitelist) ->
`useRecentHistoryStore` (Zustand + persist, key='recentHistory').
The 20-entry cap and per-fileUri dedup behavior is preserved.

Both feature modules (`features/playlists/index.ts` and
`features/recentHistory/index.ts`) keep their public API
(`usePlaylists`, `usePlaylists + useRecentHistory`, the
`playlistActions` namespace, the standalone
`createPlaylist`/`addItemToPlaylist`/`importPlaylist`/
`updatePlaylistItemPosition`/`addRecent`/`removeRecent`/
`clearRecent` helpers). They now read/write the zustand stores
directly; the old `dispatch` + `getState` `PlaylistStoreAccess`
parameter is gone.

Junior-dev rule honored: each consumer imports just
`usePlaylistsStore` / `useRecentHistoryStore` (or the type
aliases) from `../state`. The feature module

point for everything else; downstream code (Player sheet,
queue screen, archive, etc.) never touches the store directly.
